A Gradle plugin that scans Spring Boot `@RestController` classes for the endpoints they expose and reports every one that is not described in your OpenAPI documentation - a "shadow API".

Shadow APIs are endpoints that exist in code but not on paper: undocumented, unreviewed, and invisible to API consumers and security review alike. This plugin gives teams a repeatable way to catch them before they ship.

.Groovy DSL (`build.gradle`)

----

}
----

.Kotlin DSL (`build.gradle.kts`)
[source,kotlin]
----
plugins {
    id("com.arc-e-tect.shadow-api-detector") version "<version>"
}
----

== How it works

1. Every Java source file under the configured controller directories is parsed and scanned for classes annotated with `@RestController`. This is an MVP restriction - only Spring MVC's annotation-based REST controllers are recognised.
2. For each `@RestController` class, the class-level `@RequestMapping` base path (if any) is combined with every method-level `@RequestMapping`, `@GetMapping`, `@PostMapping`, `@PutMapping`, `@DeleteMapping`, and `@PatchMapping` to build the full set of exposed endpoints, each with its HTTP verb and path template.
3. The configured root OpenAPI document is parsed, following every `$ref` link - including links to other documents, resolved relative to the root document - to build the full set of described endpoints.
4. Endpoints are matched by HTTP verb and by path template; path variables are matched positionally, so `{id}` in a controller matches `{userId}` in the OpenAPI document. A `@RequestMapping` that does not restrict its HTTP method is considered described as soon as any verb is documented for a matching path.
5. Every exposed endpoint with no match is a shadow API. An AsciiDoc report listing them is written to the configured report directory - the report is always written, whether or not the build is configured to fail.

[NOTE]
====
This is a scope restriction of the current MVP, not a design limit: only `@RestController`-based endpoints are scanned, and only "exposed but undocumented" is reported (the reverse case - documented but unimplemented - is out of scope). Both may be lifted in a future release.
====

== Configuration

The plugin registers a `shadowApiDetector` extension.

.Groovy DSL
[source,groovy]
----
shadowApiDetector {
    // One or more directories to search recursively for @RestController classes.
    // Default: src/main/java
    controllerDirs.from('src/main/java')

    // The root OpenAPI document. Required - every other document is expected to be
    // reachable from this one via $ref links relative to it.
    rootDocument = file('src/main/resources/openapi/openapi.yaml')

    // Directory where the OpenAPI documentation is stored, tracked so that a change to
    // any linked document invalidates the task's cached result.
    // Default: rootDocument's own parent directory
    openApiDir = file('src/main/resources/openapi')

    // Whether the build should fail when shadow APIs are found. The report is written
    // either way.
    // Default: false
    failOnShadow = false

    // Directory the AsciiDoc report is written to.
    // Default: layout.buildDirectory.dir('reports/shadow-api-detector')
    reportDir = layout.buildDirectory.dir('reports/shadow-api-detector')

    // Name of the generated AsciiDoc report file.
    // Default: 'shadow-apis.adoc'
    reportFileName = 'shadow-apis.adoc'
}
----

.Kotlin DSL
[source,kotlin]
----
shadowApiDetector {
    controllerDirs.from("src/main/java")
    rootDocument.set(file("src/main/resources/openapi/openapi.yaml"))
    failOnShadow.set(false)
    reportDir.set(layout.buildDirectory.dir("reports/shadow-api-detector"))
    reportFileName.set("shadow-apis.adoc")
}
----

`rootDocument` is the only property that must be set - in all but very rare cases (an OpenAPI description split across many top-level documents with no single entry point) the root document is all the plugin needs, since it is expected to link to every other document itself.

== Task

[cols="2,1,3",options="header"]
|===
| Task name           | Group        | Description
| `detectShadowApis`  | verification | Scans `@RestController` classes and reports endpoints not described in the OpenAPI documentation.
|===

The task is automatically wired into the `check` lifecycle task once the `java` plugin is applied, so running `./gradlew check` always regenerates the report.

Running the report explicitly:

[source,shell]
----
./gradlew detectShadowApis
----

== Report output

After the task runs, an AsciiDoc report is written to the configured `reportDir` (default: `build/reports/shadow-api-detector/shadow-apis.adoc`), listing every shadow API grouped by declaring controller class, with its HTTP verb, path, handler method, source file, and line number.

Every report opens with a preamble explaining what a shadow API is, how it differs from a zombie API, what the risks are, and a link to the https://owasp.org/API-Security/editions/2023/en/0x11-t10/[OWASP API Security Top 10] (specifically https://owasp.org/API-Security/editions/2023/en/0xa9-improper-inventory-management/[API9:2023 Improper Inventory Management]). The preamble text lives in its own bundled resource - `shadow-api-preamble.adoc` in the plugin's `src/main/resources` - so it can be revised independently of the report-writing code.

When `failOnShadow` is `true` and at least one shadow API was found, the task fails the build after writing the report, so the report is always available for inspection regardless of build outcome.

== Full example

[source,groovy]
----
plugins {
    id 'java'
    id 'org.springframework.boot' version '<version>'
    id 'com.arc-e-tect.shadow-api-detector' version '<version>'
}

shadowApiDetector {
    rootDocument = file('src/main/resources/openapi/openapi.yaml')
    failOnShadow = true
}
----

With this setup, running `./gradlew check` will fail the build - after writing the report - as soon as any `@RestController` endpoint is found that is not described in `openapi.yaml` or any document it links to.
