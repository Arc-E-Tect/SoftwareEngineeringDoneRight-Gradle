= Multi-Module Example
:toc: left

== Description

This example applies the Architecture Validator plugin to a multi-module project with `app`, `adapters`, and `domain` subprojects.
Each module runs architecture checks independently, and the root project can aggregate the module reports.

== Intent

This example is intended to show how architecture rules behave in a modular Gradle build.
It demonstrates both per-module validation and centralized report collection.

== Build And Run

[source,bash]
----
cd examples/architecture-validator/multi-module
./gradlew clean testArchitecture
./gradlew aggregateArchitectureReports
----

== What To Expect

The `app` module depends directly on `DatabaseAdapter` from the `adapters` module.
That crosses the Hexagonal boundary and is reported by `:app:testArchitecture`.
The subprojects are configured with `ignoreFailures = true`, so the build can complete while still surfacing violations in the reports.

== Applying The Plugin Per Module

The root `build.gradle` applies the plugin once, inside `subprojects { }`, and lets each module
derive its own `basePackage` from `project.name` — each subproject only needs its own package
patterns:

[source,groovy]
----
subprojects {
    apply plugin: 'java'
    apply plugin: 'com.arc-e-tect.architecture-validator'

    architectureValidator {
        basePackage = "com.arc_e_tect.example.multi.${project.name}"
        ignoreFailures = true
        hexagonalArchitecture {
            domainModel = ['..domain..', '..model..']
            adapters = ['..adapters..', '..adapter..', '..persistence..']
            applicationServices = ['..service..']
            inPorts = ['..port.in..']
            outPorts = ['..port.out..']
        }
    }
}
----

== Reports

Each module writes its own reports under its local `build/reports/architecture-validator/` directory.
The root `aggregateArchitectureReports` task copies all module reports into `build/reports/architecture-validator/aggregate/`:

[source,groovy]
----
tasks.register('aggregateArchitectureReports', Copy) {
    dependsOn(subprojects.collect { it.tasks.named('testArchitecture') })
    into(layout.buildDirectory.dir('reports/architecture-validator/aggregate'))
    subprojects.each { subproject ->
        from(subproject.layout.buildDirectory.dir('reports/architecture-validator')) {
            into(subproject.name)
        }
    }
}
----

This is a plain Gradle `Copy` task, not plugin functionality — the pattern is reusable in any
multi-module build that wants one place to look at every subproject's report.

== Suggested Fix

Move the adapter behind an outbound port in the app module.
Let the `adapters` module implement that port instead of being referenced directly by the service.
