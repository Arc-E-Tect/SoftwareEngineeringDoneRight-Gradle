= Tracker Lens — Custom Dashboard Template Example
:toc: left

== Description

The same single-tracker setup as `../plain`, plus a project-supplied Mustache template,
`dashboard-template.html`, overriding the plugin's own bundled `dashboard.html` structure and
wording via `trackerLens.template`.

== Intent

This example shows that the dashboard's *content contract* (`DASHBOARD-THEMING.adoc`,
`ContractRule` — the `.dashboard`, `.tracker[data-tracker]`, `.metric-card[data-stage]`, and so on
selectors every lens styles against) is independent of its *document structure and wording*. The
bundled template's headings, captions, and markup nesting are just that template's own choices —
a project can supply a completely different layout, in a different language, with different
headings, and the generated dashboard is still validated against exactly the same contract and
still works with any lens, built-in or custom.

== The Template

`dashboard-template.html` renders every tracker as an `<article>` instead of a `<section>`, metrics
as a `<ul>` instead of a grid of `<div>`s, and reworded headings ("Weekly Progress Report", "Tracker:
{{id}}", "Needs A Look" instead of "Stale Items") - but keeps every contract-bound class and
attribute untouched:

[source,html]
----
<article class="tracker" data-tracker="{{id}}">
<h2>Tracker: {{id}}</h2>
<ul class="metrics">
{{#metrics}}
<li class="metric-card" data-stage="{{stage}}" style="--percent: {{percent}}">
{{stage}}: {{count}} of {{totalCount}} ({{percent}}%)
</li>
{{/metrics}}
</ul>
...
</article>
----

The `id="lens-select"` and `id="lens-stylesheet"` elements are also kept exactly as the bundled
template names them - those two ids are what the dashboard's own bootstrap script looks up at
runtime to wire up the lens switcher, independent of the content contract.

== Configuration

[source,groovy]
----
trackerLens {
    template = file('dashboard-template.html')

    trackers {
        register('bdd-scenarios') {
            historyFiles.from(file('gherkin-progress-history.ndjson'))
            source = com.arc_e_tect.gradle.trackerlens.TrackerSourceKind.GHERKIN_SCENARIO
        }
    }
}
----

== Build And Run

[source,bash]
----
cd examples/tracker-lens/custom-dashboard-template
./gradlew generateTrackerLensDashboard
----

== What To Expect

The build is expected to pass, including the same `ContractRule` validation every dashboard goes
through regardless of which template rendered it. Open
`build/reports/tracker-lens/dashboard.html` and compare it to `../plain`'s output: different
headings and markup, same working lens switcher and chart, same metric counts for the same data.
