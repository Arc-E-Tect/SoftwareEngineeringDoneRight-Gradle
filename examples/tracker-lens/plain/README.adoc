= Tracker Lens — Plain Example
:toc: left

== Description

The minimal possible `tracker-lens` setup: one tracker, `bdd-scenarios`, reading a single Gherkin
scenario progress-history file, with no custom lens, no external style pack, and no custom
template — just the plugin's built-in `dark-lens`, `light-lens`, and `high-contrast-lens`.

== Intent

This example is the starting point for everyone else in `examples/tracker-lens/`. It shows the
smallest possible `trackerLens { trackers { ... } }` block and what the generated dashboard looks
like with nothing else configured: a single tracker section with a metric card per stage, a
projection block once enough history is available, and a lens switcher offering only the built-ins.

== The Sample Data

`gherkin-progress-history.ndjson` isn't committed to this repository - it's generated fresh by
`generateTrackerLensFixture` before every dashboard build (see "Configuration" below), calibrated
so the resulting forecast lands roughly 30 days out from whenever you actually run it, not from a
snapshot frozen at some point in the past. This example exists to show what a plain dashboard looks
like, and a dashboard built from data dated to today is a truer picture of that than one built from
a file that gets staler every day it sits in git.

Left at its defaults, the generated fixture spreads a handful of scenarios across all three stages -
enough to populate every metric card, and enough history for a projection block once the earliest
of them clears the plugin's minimum lookback window. See `tracker-lens`'s own `README.adoc` for
exactly what `generateTrackerLensFixture` guarantees.

== Configuration

[source,groovy]
----
trackerLens {
    trackers {
        register('bdd-scenarios') {
            historyFiles.from(file('gherkin-progress-history.ndjson'))
            source = com.arc_e_tect.gradle.trackerlens.TrackerSourceKind.GHERKIN_SCENARIO
        }
    }
}

// Regenerates a calibrated sample fixture, dated to whenever this project is actually built,
// before every dashboard render - never a snapshot that goes stale the moment it's committed.
tasks.named('generateTrackerLensDashboard') { dependsOn 'generateTrackerLensFixture' }
----

== Build And Run

[source,bash]
----
cd examples/tracker-lens/plain
./gradlew generateTrackerLensDashboard
----

== What To Expect

The build is expected to pass. `generateTrackerLensFixture` runs first (wired as a dependency
above), writing a fresh `gherkin-progress-history.ndjson`; the plugin then writes
`build/reports/tracker-lens/dashboard.html`, containing:

* One `.tracker[data-tracker="bdd-scenarios"]` section.
* Three `.metric-card` elements — `listed`, `defined`, `implemented` - each scenario's *current*
  stage (mutually exclusive, summing to the total scenario count), not a cumulative "reached at
  least this stage" count — a scenario that's already `implemented` no longer counts toward
  `listed` or `defined`. Exact counts vary run to run, since the underlying data is regenerated
  fresh each time.
* A `.projection` block projecting when the remaining scenarios will reach `implemented`, based on
  the historical rate at which earlier ones did.
* A `.lens-switcher` offering `dark-lens`, `high-contrast-lens`, and `light-lens`.

No `lensStyle` dependency and no `lensStylesheet` are configured, so no `custom-lens` or external
pack lens appears — see `../custom-lens` and `../external-lens-pack` for those.
