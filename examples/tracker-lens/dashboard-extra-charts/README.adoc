= Tracker Lens — Dashboard Extra Charts Example
:toc: left

== Description

Two trackers - `bdd-scenarios` (Gherkin scenarios) and `api-contracts` (API contracts) - rendered by
a project-supplied Mustache template, `dashboard-template.html`, overriding the plugin's own
bundled `dashboard.html` via `trackerLens.template`. The template's structure and wording are
identical to the bundled one (see `../custom-dashboard-template` for an example that changes those
instead); the only difference here is two extra, non-contract charts it adds beside each tracker's
built-in line chart.

== Intent

This example shows that a project-supplied template isn't limited to what `TrackerView` and
`MetricCardView` hand it via Mustache (`{{#metrics}}`, `{{#projection}}`, and so on) - it can add
its own markup and its own script to derive additional views the plugin itself never computes:

* Beside `bdd-scenarios`'s line chart, a *pie chart* of the three Gherkin stages
  (`listed`/`defined`/`implemented`). Each stage's count from `#dashboard-data` is cumulative -
  "reached at least this stage" - so the pie's slices are each stage's count *minus* the next
  stage's count, giving three mutually-exclusive buckets that sum to the tracker's total.
* On `api-contracts`' own metric cards - `declared`, `implemented`, `verified` - a hover-over "?"
  badge on each term, explaining the full compound condition it actually checks.
* Beside `api-contracts`' line chart, three small *pie charts*: total APIs vs. Undefined, total
  vs. Unimplemented, total vs. Unverified - named after what's missing rather than after the
  detector plugin that finds it, though they're the same three problem endpoints this repository's
  own `shadow-api-detector` (Undefined - implemented, no OpenAPI description), `mirage-api-detector`
  (Unimplemented - described, no implementation), and `doppelganger-api-detector` (Unverified -
  described and implemented, no test confirming the two agree) look for.

=== Why declared/implemented/verified don't sum to 100%

`declared`, `implemented`, and `verified` are three *independent* checks on the same 12 endpoints -
not stages of one pipeline the way `bdd-scenarios`' `listed`/`defined`/`implemented` are. An
endpoint can satisfy zero, one, two, or three of them independently, so nothing says their
percentages (75%, 83%, 33%) have to sum to 100%, and they don't - visible directly on the metric
cards themselves.

The three pies beside the line chart show a related but different thing: each one is internally
consistent on its own (a slice and its complement always sum to 100%) - what they add is a
concrete look at how much of the 12 endpoints each specific check is currently failing, side by
side: Undefined 3 (25%), Unimplemented 2 (17%), Unverified 3 (25%).

== The Template

`dashboard-template.html` keeps the bundled template's `<section class="tracker">`, `<h2>{{id}}</h2>`,
`.metrics` grid of `.metric-card` divs, and `.projection` markup exactly as-is, plus one small
addition - a `data-total="{{totalCount}}"` attribute on each metric card, since `totalCount` is
rendered into the static markup but never included in the `#dashboard-data` JSON blob, which
carries only per-stage counts, and the three pies' script needs it to compute each detector's
share:

[source,html]
----
<div class="metric-card" data-stage="{{stage}}" data-total="{{totalCount}}" style="--percent: {{percent}}">
----

The only structural addition beyond that is wrapping each tracker's `.chart` div in a flex row
alongside a second, empty `.chart-extra` div the template's own script fills in:

[source,html]
----
<div class="charts-row">
<div class="chart"><canvas></canvas></div>
<div class="chart-extra" data-extra-chart-for="{{id}}"></div>
</div>
----

=== The Hover-Over Definitions

A small circled `?`, appended next to `declared`/`implemented`/`verified` on api-contracts' own
metric cards (not on the pies - those are a separate concern below), carries the term's full
definition as a plain HTML `title` attribute, so hovering it shows the browser's native tooltip
with no extra library. It's attached only within `.tracker[data-tracker="api-contracts"]`, since
`bdd-scenarios` has its own, unrelated `implemented` stage (Gherkin scenarios, not API endpoints)
that these definitions don't describe:

[source,javascript]
----
var STAGE_DEFINITIONS = {
  declared: 'An OpenAPI description exists, but no implementation.',
  implemented: 'Endpoint is implemented using Spring RestController, but there is no OpenAPI description.',
  verified: 'An OpenAPI description exists, the endpoint is implemented using Spring RestController, '
      + 'and at least one test exists that validates the implementation matches the OpenAPI description.'
};
----

== The Sample Data

`api-contract-history.ndjson` has 12 endpoints: 3 Shadow, 2 Mirage, 3 Doppelganger, and 4 Compliant
- e.g. `GET /api/internal/debug-info` (implemented, never declared: Shadow),
`DELETE /api/orders/{id}/archive` (declared, never implemented: Mirage),
`PATCH /api/customers/{id}` (declared and implemented in June, still not verified: Doppelganger),
and `GET /api/orders/{id}` (declared, implemented, and verified: Compliant).

== Configuration

[source,groovy]
----
trackerLens {
    template = file('dashboard-template.html')

    trackers {
        register('bdd-scenarios') {
            historyFiles.from(file('gherkin-progress-history.ndjson'))
            source = com.arc_e_tect.gradle.trackerlens.TrackerSourceKind.GHERKIN_SCENARIO
        }
        register('api-contracts') {
            historyFiles.from(file('api-contract-history.ndjson'))
            source = com.arc_e_tect.gradle.trackerlens.TrackerSourceKind.API_CONTRACT
        }
    }
}
----

== Build And Run

[source,bash]
----
cd examples/tracker-lens/dashboard-extra-charts
./gradlew generateTrackerLensDashboard
----

== What To Expect

The build is expected to pass, including the same `ContractRule` validation every dashboard goes
through regardless of which template rendered it. Open `build/reports/tracker-lens/dashboard.html`:

* `bdd-scenarios` (5 scenarios total: `listed` 5, `defined` 4, `implemented` 3) shows its usual line
  chart plus a pie chart with slices 1 (`listed` only), 1 (`defined` only), 3 (`implemented`).
* `api-contracts` (12 endpoints total: `declared` 9, `implemented` 10, `verified` 4) shows a `?`
  badge on each of its three metric cards, its usual line chart, and three pies beside it:
  Undefined 3/12 (25%), Unimplemented 2/12 (17%), Unverified 3/12 (25%).

Switching lenses still works exactly as in `../plain`, since the lens switcher and every
contract-bound element are untouched - only the two added charts and their surrounding layout are
this template's own, unlensed markup.
