= Shadow API Detector — With Shadow APIs Example
:toc: left

== Description

This example applies the Shadow API Detector plugin to an `InvoiceController` that has drifted out of sync
with its OpenAPI document: a `DELETE /invoices/{id}` endpoint was added to the code but the document was
never updated. `failOnShadow` is enabled, so the build fails once the mismatch is detected.

== Intent

This example is intended to show what a failing shadow-API detection run looks like, and that the AsciiDoc
report is still written even though the build fails - so the mismatch is always visible, not just reported
as a bare failure.

This is the plugin's canonical "why this exists" example: undocumented endpoints are exactly what
`shadowApiDetector` is meant to catch before they ship.

== The Controller

[source,java]
----
@RestController
@RequestMapping("/invoices")
public class InvoiceController {

    @GetMapping
    public String listInvoices() { ... }

    @GetMapping("/{id}")
    public String getInvoice(@PathVariable Long id) { ... }

    @PostMapping
    public String createInvoice(@RequestBody String invoice) { ... }

    // Added after the OpenAPI document was last updated - never described.
    @DeleteMapping("/{id}")
    public void deleteInvoice(@PathVariable Long id) { ... }
}
----

Full source: `src/main/java/com/arc_e_tect/example/invoicing/InvoiceController.java`.
The OpenAPI document - `src/main/resources/openapi/openapi.yaml` - only describes `GET /invoices`,
`GET /invoices/{id}`, and `POST /invoices`.

== Build And Run

[source,bash]
----
cd examples/shadow-api-detector/with-shadow-apis
./gradlew detectShadowApis
----

`./gradlew build` fails the same way: this example wires `detectShadowApis` into the `check` lifecycle task
explicitly in `build.gradle`, since the plugin does not do so automatically.

== What To Expect

The build is expected to fail:

[source]
----
> Task :detectShadowApis FAILED
shadowApiDetector: found 1 shadow API(s) not described in the OpenAPI documentation. See .../shadow-apis.adoc
----

`build/reports/shadow-api-detector/shadow-apis.adoc` is still written before the failure. It opens with a
preamble explaining what a shadow API is (see link:../../../shadow-api-detector/README.adoc[the plugin
README]'s "Report output" section), then lists the undocumented endpoint:

[source,asciidoc]
----
== Shadow APIs

=== com.arc_e_tect.example.invoicing.InvoiceController

[cols="1,3,3,2,1",options="header"]
|===
| HTTP Verb | Path | Method | Source File | Line

| DELETE
| /invoices/{id}
| deleteInvoice(Long)
| InvoiceController.java
| ...
|===
----

== Suggested Fix

Either add a `delete: ...` operation for `/invoices/{id}` to the OpenAPI document, or remove the endpoint
from the controller if it was never meant to be public.
